# 能力ギャップから Skill 候補を作成

既存の Skill では満たせない範囲限定の能力ギャップを、候補専用の隔離状態へ変換します。明示的な呼び出し専用です。

## 使う時

- 繰り返し得られた独立した証拠または継続的な再発防止に役立つ成果物がギャップを示し、既存の Skill では安全に満たせない時
- 機微情報を除いた証拠に、再現条件、安定した入出力、決定論的な検証がある時
- ユーザーが絶対パスの `candidate_path`、対象 Git ルート、候補名、候補専用の書き込み権限を明示した時

## 使わない時

一回限りの事象、未検証のもの、秘密情報、認証情報、個人情報、未加工ログ、有効な Skill の更新・インストール・昇格、候補パス/所有者/対象/検証器が不明な時。

## 手順

1. `update-existing`、`dismiss`、`new-candidate`を、証拠と既存 Skill の一覧に照合する。判断できなければ止める。
2. 絶対パスでシンボリックリンクではない空のディレクトリとして候補パスを固定し、候補専用の権限を `SKILL.md` と `agents/openai.yaml` に限定する。
3. 本文には、発動条件、機微情報を除いた入力、範囲限定の出力、権限、検証、対象外、昇格ゲートだけを書く。
4. `scripts/validate_skill_candidate.py --target-repo-root ... --candidate-path ...`を実行し、有効な Skill、対象リポジトリ、親ワークスペース、他の候補を変更しない。
5. 検証器が成功した後もライフサイクルは `needs_human` とし、昇格の判断を返す。

## 出力

判定、候補/対象パス、適格性、ライフサイクル、検証結果、内容ダイジェスト、未解決の昇格判断、残るリスク。

## 安全

Git、外部操作、インストール、昇格、クリーンアップ、名前変更、有効な Skill の編集を行いません。秘密情報、トークン、認証情報、パスワード、鍵、認証データ、個人情報、未加工のツール出力を扱いません。検証器のダイジェストはスナップショットや承認の代替ではありません。

## 停止条件

適格性不足、既存の Skill で解決、パスの衝突、シンボリックリンク、検証失敗、権限不足、または候補を作成して `needs_human` ゲートを返せた時。
