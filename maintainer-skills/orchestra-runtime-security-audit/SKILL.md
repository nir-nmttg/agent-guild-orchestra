# 実行補助機構のセキュリティ監査

`git_guard`、`snapshot_digest`、`config`、エージェントのサンドボックス、追加用の補助スクリプトによるパス/argv/信頼できない入力の処理を、実装と意味の両面から読み取り専用で監査します。明示的な呼び出し専用です。

## 使う時

- 実行補助機構の補助スクリプト、`config`、エージェントのサンドボックス、Git/スナップショット、ブラウザー/VS Code の補助スクリプトを変更した時
- セキュリティ、パス封じ込め、シンボリックリンク、コマンドインジェクション、範囲逸脱、信頼できない出力の独立監査が必要な時
- インストーラーまたは大規模な再設計後に旧キュー/Ledger/フックの権限経路を確認する時

## 手順

1. 対象、範囲、権限、差分、維持する受け入れ条件を読み取り専用で固定する。
2. 正規パス、シンボリックリンク、argv、範囲、処理前/処理後のスナップショット、ダイジェスト、失敗状態をフェイルクローズで扱うか確認する。モデル出力やログをメタデータ/権限の根拠にしない。
3. サンドボックス、承認、エージェント設定、明示呼び出し専用パッケージ、フック/署名のスキップ、認証情報に似たファイル名の判定規則を実装とドキュメントで照合する。
4. Git LFS/コンテンツフィルターを使うリポジトリと、追跡対象の末端シンボリックリンクを未対応（unsupported）として停止する境界を、機微情報を含まない一時フィクスチャで確認する。
5. 証拠、重大度、判定、未確認範囲、最小修正条件、残るリスクを返す。必要な時だけ重要な独立レビューを提案する。

## 出力

監査対象、境界、フィクスチャ/テスト、観測した証拠、Critical/Major/Minor、未確認範囲、修正条件、残るリスク。

## 安全

読み取り専用であり、実行補助機構の状態、Git、外部サービス、インストーラー、導入先を変更しません。秘密情報、認証情報、トークン、パスワード、鍵、認証データ、個人情報、未加工ログを扱いません。破壊的操作、依存関係の追加、移行、デプロイ、外部更新は行いません。

## 停止条件

対象、証拠、重大度、修正条件、残るリスクを報告できた時、または機微情報、対象不明、古いスナップショット、安全な再現経路の不足が判明した時。
